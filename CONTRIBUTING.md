# Contributing

Start with the executed research notebook linked from README.md. Reusable Python
belongs in `src/`; notebook cells explain decisions and expose results. The web
application reads static JSON generated by the notebook.

Before proposing changes:

1. Keep raw Yelp archives, credentials, labeling records and local environments
   out of Git. Read DATA_AND_LICENSES.md before adding data or excerpts.
2. Run `python3 scripts/audit_public_repo.py --history` for publication changes.
   This focused scan is supplementary to manual data and secret review.
3. Run `python scripts/check_docs.py` after documentation changes. Follow
   [maintenance](docs/maintenance.md) for rebuild scope. Run Python and JavaScript tests using the README commands.
4. For data changes, rerun the research notebook and include its executed outputs,
   generated datasets and build manifest together. UI-only builds must not replace
   notebook-generated data.
5. Explain changes to denominators, time windows, model support or interpretation.
   Preserve missing values instead of substituting zero. Label historical findings
   separately from predictions and causal claims.

Do not change repository visibility, publish Pages, or rewrite Git history as part
of routine cleanup. Complete the release audit first. Avoid reporting credentials
or private data in public issues; coordinate privately with the repository owner.
